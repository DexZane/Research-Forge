# Researchability and Fit Preflight Protocol

## Purpose

Turn a broad interest or favored idea into a bounded, answerable research question before deep literature work or candidate ranking. This protocol assesses whether the project can reach a meaningful discriminating observation within the user's real constraints; it does not estimate publication success.

## Research Question Canvas

Create one `RQ-` canvas during S00/S01 with:

1. `phenomenon`: the observed or reported symptom, with epistemic status;
2. `unit_and_condition`: system, task, data/setting, and boundary;
3. `knowledge_gap`: what is unknown rather than merely untried;
4. `mechanism_question`: the relation to explain or discriminate;
5. `observable_outcome`: an observation that could answer the question;
6. `minimal_discriminating_path`: the cheapest plausible route to that observation;
7. `scope_ladder`: minimum-completable, core-project, and extension scopes;
8. `stop_or_reframe_condition`: what would make the current question not worth pursuing.

Do not replace a missing phenomenon or knowledge gap with a module name, benchmark target, title, or generic performance claim. Mark unavailable decision-critical information `UNKNOWN` and create debt.

## Fit Card

Create one `FIT-` record for the project. Separate:

- hard constraints: deadline, compute, data access, licensing/ethics, required expertise, mentor/team availability, and required tooling;
- preferences: interests, career relevance, target venues, and preferred methods;
- uncertainty: verified availability, assumed availability, and explicit dependency owner.

Interest, career goals, target venue, and a supervisor's preference can determine whether a project is worth considering. They cannot establish novelty, a mechanism, feasibility, or a scientific claim.

## Scope Ladder

Write three nested scopes rather than one oversized project:

- `MINIMUM_COMPLETABLE`: the least work that can yield a valid discriminating observation;
- `CORE_PROJECT`: the evidence required for the intended scientific contribution;
- `EXTENSION`: valuable generalization or scale work that is explicitly non-blocking.

Every scope lists inputs, output, time/compute assumptions, and its stop condition. Do not call an extension a minimum requirement or quietly use an unavailable core dependency in the minimum scope.

## Preflight Outcomes

- `PROCEED`: canvas is answerable and the minimum path is plausible; carry unknowns into S02.
- `HOLD_SCOPE`: a user or mentor decision changes scope materially; remain at G1.
- `HOLD_RESOURCE`: the question remains meaningful, but no minimum path is currently possible; preserve it without forcing a weaker question.
- `REFRAME`: narrow the unit, condition, mechanism, or observation and return to S00/S01.

Do not issue scientific `KILL` merely because a novice lacks a skill or resource; record the gap and distinguish a capability plan from scientific validity.

## G1 Requirement

G1 contains the RQ canvas, FIT card, scope ladder, decision-critical unknowns, and a list of questions for the human/mentor. Human advice is logged as a classified human-input record; it is not source evidence unless it supplies a verifiable artifact or changes a declared constraint.
