# Candidate Schema

## Required Fields

`C-` ID, genealogy parents/relation, mechanism-oriented title, research/mechanism question, initial gap, predictions, closest work, threats, risks, implementation guess, novelty/residual/status, evidence, version, and kill reason when archived.

## Validity

- Candidate is a scientific question plus mechanism, not a module combination.
- Active candidate has at least one observable preliminary prediction and risk.
- Novelty begins `UNVERIFIED`; only S10 can assign a bounded survivor status.
- Candidate lineage uses `ORIGIN`, `REFINES`, `NARROWS`, `PIVOTS`, `MERGES`, `SPLITS`, or `REVIVES`.
- Revival requires new evidence, scope, mechanism, or constraint; sunk cost is invalid.
- KILL preserves candidate, ancestors, killed claims, evidence, and decision.

## Portfolio Invariants

Exploration mode S06 has 8–15 diverse candidates before S07. Idea-validation mode includes original, refined, and alternative-mechanism candidates. G2 selects at most 1–3 finalists. Pareto domination removes depth-search priority but does not erase history.
