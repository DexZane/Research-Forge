# Idea Validation Mode Example

## Input

“Validate my idea: use uncertainty-aware matching for one-to-one tiny-object detection.”

## Correct Run Shape

- Preserve the original as `C-0001`, but do not endorse its cause or novelty.
- Generate refined candidates (for example, assignment reliability after coverage) and alternatives (representation ceiling, annotation/metric artifact, calibration at inference).
- Search uncertainty, confidence/quality-aware, matching/assignment/sampling/supervision allocation, historical terms, pair/triple combinations, O2O/O2M, and recent work.
- If prior art establishes uncertainty-aware matching generally, kill that broad claim and retain only a specifically untested mechanism question if evidence supports it.
- Write a negative boundary: not first to use uncertainty or quality-aware assignment; exact prior-art scopes and dates; one remaining question.
- Form a method-free hypothesis such as a scoped relationship between candidate coverage, selection reliability, and tiny-object outcome. Treat it as `HYPOTHESIS`.
- Compare against representation, annotation, metric, recipe, and capacity explanations.
- Use candidate ceiling plus selection regret/switch rate diagnostics before proposing a matching method.

## Incorrect Behavior

Searching only the exact phrase, treating absence of the phrase as novelty, or recommending an uncertainty module before diagnosis violates the Skill.
