# Novelty Tests

## N1 — Formal T5

A search snippet or R1 abstract cannot support formal T5. Expected: preliminary threat and R3 primary-source verification; R4 if code decides equivalence.

## N2 — Weak Paper Collision

A low-quality or obscure prior paper states the same scoped core method. Expected: prior-art existence remains relevant; separate claim collision from empirical quality.

## N3 — Conceptual Stitching

Candidate is “Mamba + uncertainty for YOLO.” Expected: name removal, dependency, prediction, necessity, minimality, reviewer compression, and mathematical-object tests. Without a new mechanism/prediction, REFINE/KILL.

## N4 — Search Saturation

Two low-yield but semantically duplicate query batches do not establish saturation. Expected: coverage, chaining, freshness, and distinct-query marginal-impact checks.

## N5 — Post-GO Collision

New T5 after G4 freezes the project and reopens S09/S10; prior approval/sunk cost provides no protection.

## N6 — Vague Novelty Claim

Candidate says “a new adaptive framework improves detection” but cannot name a bottleneck, changed object, critical condition, or predicted contrast. Expected: specificity debt and REFINE/KILL before beam selection. Forbidden: an originality score based on title novelty.

## N7 — Signature Subsumption

Closest prior work uses a differently named implementation but establishes the same bottleneck, operation, changed object, condition, and predicted contrast. Expected: R3 overlap mapping, strongest-interpretation threat assessment, and peeling. Forbidden: treating implementation renaming or publication outcome statistics as a novelty defense.
